# Portal-generated PFI (Pro-Forma Invoice) PDF — design

**Date:** 2026-10-19 · **Status:** approved in chat, awaiting written-spec review
**Portal sides:** Admin/Staff (Generate PFI, Orders page link) · Dealer (View PFI)

## Goal

When an Admin or Sales Person Executive clicks **Generate PFI**, the portal itself produces the
PFI, laid out like Trinity's Odoo "PRO-FORMA INVOICE" (template: `Sale PRO-FORMA Invoice - S01177.pdf`),
**without any manual step in Odoo**. Dealers and staff open it as a PDF before payment.

## Decisions (from the user)

| Topic | Decision |
|---|---|
| Source of the PDF | Generated by the portal (not Odoo's PDF); Odoo is not contacted at PFI time |
| VAT | **8%, included in the price.** Portal unit prices (EPRA pump price − KSh 3) already include VAT |
| Prepared By / Approved By | Both = the staff member who clicked Generate PFI, with that date |
| When | Staff click **Generate PFI** (today's step); not automatic |
| Who sees it | The dealer (own organisation only) and Admin / Sales Person Executive |
| Approach | Freeze the PFI's data when generated; draw the PDF on each request (pdfkit, server-side). No file storage |
| Colours | Primary blue `#3854a3`; footer gradient `#3854a3` → `#32c1d1` |

## 1. Data (one migration)

- `DealerOrderLine.unitPriceInclVat String?`: the VAT-inclusive unit price (KES/L, 2 dp) **at quotation time**.
  `syncQuotation` stores the same value it sends to Odoo (`epraUnitPriceForStation`).
- `DealerOrder.quotedAt DateTime?`: set when the quotation is saved. It is the "SO DATE" on the PFI.
- `ProFormaInvoice` gains:
  - `subtotal String`, `vatAmount String`, `vatRate String` (`"0.08"`);
  - `preparedById String?` (a relation to User, `onDelete: SetNull`) and `preparedByName String` (frozen display name).

  The existing `amount` stays the **Total**.

Existing rows: the new columns are nullable or defaulted, so the migration is additive only.

## 2. PFI maths: `src/lib/orders/pfi-totals.ts` (pure)

`pfiTotals(lines: { product, quantityLitres, unitPriceInclVat: string }[], vatRate = 0.08)` returns:
- per line: `unitPriceExVat` (number, full precision), `amountExVat` (2 dp);
- `subtotal`, `vat`, `total` (2 dp strings).

**Rule:**
- `total` = Σ round(litres × unitPriceInclVat, 2);
- `subtotal` = round(total ÷ (1 + rate), 2);
- `vat` = total − subtotal;
- line `amountExVat` = round(litres × unitPriceInclVat ÷ (1 + rate), 2).

Line amounts can differ from `subtotal` by a cent through rounding. That is accepted, as in Odoo.

Checked against the template: 6,000 L @ 199.94 and 10,000 L @ 203.77 give lines of 1,110,777.78 and 1,886,759.26, a subtotal of 2,997,537.04, VAT of 239,802.96 and a total of 3,237,340.00.

## 3. Generate PFI: `generatePfi(orderId, actorId)` in `src/lib/orders/service.ts`

- Same guards and state flow as today: needs a quotation; already issued → return as-is; `→ PFI_PENDING → PFI_ISSUED → AWAITING_PAYMENT`.
- **No Odoo call.** `client.generateProForma` is no longer used by the order flow.
- Line prices:
  - use `unitPriceInclVat`;
  - for an older line without one, use today's `epraUnitPriceForStation` and **save it onto the line**, so it's frozen;
  - if no price can be found (unknown station), refuse with "This station has no price yet." and leave the order at QUOTATION_READY with that note, as failures do today.
- **PFI number = the SO (quotation) number** (`odooQuotationNumber`, e.g. `S01177`).
- Saves `ProFormaInvoice` with the totals from `pfiTotals`, `preparedById` and `preparedByName` (the actor's first and last name), and sets `amountDue = total`.
- In live Odoo mode, Odoo's quotation total may differ if its tax set-up differs. **The PFI total is what the dealer pays.** Reconciling this is a Phase 4/5 concern; it is noted here, not solved.

## 4. The PDF: `src/lib/orders/pfi-pdf.ts`

`renderPfiPdf(data: PfiDocument): Promise<Buffer>` uses pdfkit, A4, with the built-in Helvetica.
`PfiDocument` is plain data assembled by `loadPfiDocument(orderId)`, so the renderer has no database access.

The layout follows the template, top to bottom:
1. The logo (`public/assets2/img/logo.png`).
2. A `#3854a3` title bar reading "PRO-FORMA INVOICE".
3. SO No. / SO DATE.
4. The customer block:
   - CUSTOMER: the dealer organisation name;
   - CUSTOMER ID: station `odooPartnerId` → organisation `odooPartnerId` → organisation code;
   - ADDRESS: station name, then "Kenya".
5. The right-hand block:
   - Payment Terms: "Immediate Payment";
   - Currency: "KES";
   - Source Location: the station's warehouse label (LakeO/Stock, KPC-NAKURU/Stock, KPC-ELDORET/Stock, KPC-KISUMU/Stock).
6. The line table, with a `#3854a3` header: ITEM NO, DESCRIPTION ("PMS LOCAL" / "AGO LOCAL"), UOM "L", VOLUME, UNIT PRICE (ex VAT, 4 dp), AMOUNT.
7. Sub Total, VAT, Total.
8. Bank Account Details: the two accounts from the template, kept as constants in `src/lib/company/bank-details.ts`.
9. Prepared By / Approved By, each with the name and date (DD.MM.YYYY).
10. A "Terms and Conditions" bar with an empty box.
11. The footer: a gradient band (`#3854a3` → `#32c1d1`) with the company name, email, website, phones and physical address, as on the template.

**Number formats:**
- amounts use thousands separators and 2 dp (`1,110,777.78`);
- volumes are shown like `6,000`;
- unit prices are shown to 4 dp.

## 5. Opening it: `GET /api/orders/[id]/pfi`

- 401 if not signed in.
- Allowed:
  - an INTERNAL user with `can(role, "retail.orders")`;
  - a DEALER whose `dealerOrganizationId` matches the order's.
- Everyone else, and orders without a PFI, get **404**, so other dealers can't tell whether an order exists.
- Response: `application/pdf`, `Content-Disposition: inline; filename="PFI-<number>.pdf"`, `Cache-Control: private, no-store`.

**Where the link appears:**
- **Dealer:** in the order page's documents list, the "Pro Forma Invoice (PFI)" row becomes a **View PFI** link (new tab) once the PFI exists.
- **Staff:** on the Orders page, the PFI number cell becomes a link.

## 6. Out of scope

- Odoo's own PDF, Odoo's `generateProForma` (left in the client, unused) and the messaging PFI-file route (unchanged).
- Terms and conditions text. Swift codes (blank on the template).
- Automatic PFI generation and emailing the PFI.

## 7. Testing

- **Unit:** `pfiTotals` against the template's figures (above), the formatting helpers, and the customer-ID fallback.
- **DB:**
  - `syncQuotation` stores `unitPriceInclVat` and `quotedAt`;
  - `generatePfi` saves the totals and prepared-by, sets amountDue = total, uses the SO number, freezes legacy line prices, and refuses an unknown station;
  - the route rule allows the own dealer and Admin/SPE, and refuses another dealer, a Staff Member and a depot user.
- **Visual:** render a generated PFI to PNG and compare it with the template.
- **Running app:** generate a PFI as SPE on a throwaway DB, then open it as the dealer and as SPE; another dealer gets a 404.
- **Full suite:** unit, DB, typecheck, lint, build.

## 8. Rollout

- **The migration is additive.** Apply it to staging, then production, with the guarded flow before deploying.
- **Production has no orders yet** (dealer ordering is off), so no backfill is needed.
