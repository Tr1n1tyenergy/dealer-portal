# Portal-generated PFI (Pro-Forma Invoice) PDF — design

**Date:** 2026-10-19 (revised the same day: VAT on top, fixed signatories, automatic PFI) · **Status:** awaiting written-spec review
**Portal sides:** Dealer (View PFI, amount due now includes VAT) · Admin/Staff (Orders page link, Generate PFI as a manual retry)

## Goal

As soon as an order's quotation is ready, the portal produces the PFI itself, laid out like Trinity's Odoo
"PRO-FORMA INVOICE" (template: `Sale PRO-FORMA Invoice - S01177.pdf`), **without any manual step in Odoo**.
The dealer can open it as a PDF and pay; staff can open it from the Orders page.

## Decisions (from the user)

| Topic | Decision |
|---|---|
| Source of the PDF | Generated by the portal (not Odoo's PDF); Odoo is not contacted at PFI time |
| VAT | **8% added on top.** The portal unit price (EPRA pump price − KSh 3) is treated as the price **before VAT** |
| Prepared By / Approved By | **Fixed names:** EVAN OTIATO for both (as on the sample), kept as constants. Date = the PFI's issue date |
| When | **Automatically**, straight after the quotation is created. No staff step |
| Who sees it | The dealer (own organisation only) and Admin / Sales Person Executive |
| Approach | Freeze the PFI's data when generated; draw the PDF on each request (pdfkit, server-side). No file storage |
| Colours and borders | Bars and table header `#2b76b6` (measured from the template); footer gradient `#3854a3` → `#32c1d1`; black 0.85pt borders, with outlines on the bars and dividers in the header row |
| Logo | `assets/pfi/logo.png` (high-resolution file supplied by the user) |
| 1:1 with the template | **US Letter** (612×792pt), **Lato Medium / Lato Bold** at the template's sizes (title 15.4, body 9, bank/signatures 7.7, terms 10.2), the template's exact positions and 0.65pt black rules, and its own footer artwork (`assets/pfi/footer.png`). Fonts: `assets/pfi/*.woff` (SIL OFL 1.1, licence alongside) |

**Effect on the amount due:** the dealer now pays the **VAT-inclusive total**, which is 8% more than the quotation total today.
The order form shows litres only, so nothing there changes. Every amount shown after the PFI (the order page and the staff Orders table) is the PFI total.

## 1. Data (one migration)

- `DealerOrderLine.unitPriceExVat String?`: the unit price before VAT (KES/L, 2 dp) **at quotation time**.
  `syncQuotation` stores the same value it sends to Odoo (`epraUnitPriceForStation`).
- `DealerOrder.quotedAt DateTime?`: set when the quotation is saved. It is the "SO DATE" on the PFI.
- `ProFormaInvoice` gains:
  - `subtotal String`, `vatAmount String`, `vatRate String` (`"0.08"`);
  - `preparedByName String` and `approvedByName String`.

  The names are copied from the constants when the PFI is issued, so a later change of signatory doesn't rewrite old PFIs.
  The existing `amount` stays the **Total (incl. VAT)**.

The migration is additive only: the new columns are nullable or defaulted.

## 2. PFI maths: `src/lib/orders/pfi-totals.ts` (pure)

`pfiTotals(lines: { product, quantityLitres, unitPriceExVat: string }[], vatRate = 0.08)` returns:
- per line: `amount` (2 dp);
- `subtotal`, `vat`, `total` (2 dp strings).

**Rule:**
- line `amount` = round(litres × unitPriceExVat, 2);
- `subtotal` = Σ line amounts;
- `vat` = round(subtotal × rate, 2);
- `total` = subtotal + vat.

Money is done in whole cents (integers) to avoid floating-point drift.

Checked against the template's figures:
- lines of 1,110,777.78 and 1,886,759.26 give a subtotal of 2,997,537.04;
- VAT = 2,997,537.04 × 8% = 239,802.96;
- total = 3,237,340.00.

## 3. Automatic PFI after the quotation

- `syncQuotation` (`src/lib/orders/service.ts`), after it saves the quotation (→ QUOTATION_READY), calls `generatePfi(orderId, actorId)` **in the same request**:
  - a dealer's new order goes straight to **AWAITING_PAYMENT** with its PFI;
  - staff "Retry sync" behaves the same way.
- `generatePfi(orderId, actorId: string | null)`:
  - Same guards and state flow as today: needs a quotation; already issued → return as-is; `QUOTATION_READY → PFI_PENDING → PFI_ISSUED → AWAITING_PAYMENT`.
  - **No Odoo call.** `client.generateProForma` is no longer used by the order flow.
  - Line prices:
    - use `unitPriceExVat`;
    - for an older line without one, use today's `epraUnitPriceForStation` and **save it onto the line**, so it's frozen;
    - if no price can be found (unknown station), the order returns to QUOTATION_READY with the note "PFI not issued: this station has no price yet.", as failures do today.
  - **PFI number = the SO (quotation) number** (`odooQuotationNumber`, e.g. `S01177`).
  - Saves `ProFormaInvoice` with the totals and the signatory names, and sets `amountDue = total`.
- **Staff "Generate PFI" stays** on the Orders page (Admin / Sales Person Executive) for orders left at QUOTATION_READY, i.e. **as a manual retry** after a failure. It's the same function.
- If the PFI step fails, the quotation is kept (it isn't rolled back); only the PFI is retried.
- In live Odoo mode, Odoo's quotation total depends on Odoo's tax set-up. **The PFI total is what the dealer pays.** Reconciling this with Odoo is a Phase 4/5 concern; it is noted here, not solved.

## 4. The PDF: `src/lib/orders/pfi-pdf.ts`

`renderPfiPdf(data: PfiDocument): Promise<Buffer>` uses pdfkit, US Letter, with Lato Medium and Lato Bold (embedded).
`PfiDocument` is plain data assembled by `loadPfiDocument(orderId)`, so the renderer has no database access.

The layout follows the template, top to bottom:
1. The logo (`assets/pfi/logo.png`).
2. A `#2b76b6` title bar reading "PRO-FORMA INVOICE".
3. SO No. / SO DATE.
4. The customer block:
   - CUSTOMER: the dealer organisation name;
   - CUSTOMER ID: station `odooPartnerId` → organisation `odooPartnerId` → organisation code;
   - ADDRESS: station name, then "Kenya".
5. The right-hand block:
   - Payment Terms: "Immediate Payment";
   - Currency: "KES (1)", as on the template;
   - Source Location: the station's warehouse label (LakeO/Stock, KPC-NAKURU/Stock, KPC-ELDORET/Stock, KPC-KISUMU/Stock).
6. The line table, with a `#2b76b6` header: ITEM NO, DESCRIPTION ("PMS LOCAL" / "AGO LOCAL"), UOM "L", VOLUME, UNIT PRICE (before VAT), AMOUNT.
7. Sub Total, VAT (8%), Total.
8. Bank Account Details: the two accounts from the template.
9. Prepared By / Approved By: the frozen names, each with the issue date (DD.MM.YYYY).
10. A "Terms and Conditions" bar with an empty box.
11. The footer: the template's own footer artwork (gradient band with company name, contacts and address).

The bank details and signatory names are constants in `src/lib/company/pfi-settings.ts`.

**Number formats:**
- amounts use thousands separators and 2 dp (`1,110,777.78`);
- volumes are shown like `6,000`;
- unit prices are printed exactly as stored (no reformatting).

## 5. Opening it: `GET /api/orders/[id]/pfi`

- 401 if not signed in.
- Allowed:
  - an INTERNAL user with `can(role, "retail.orders")`;
  - a DEALER whose `dealerOrganizationId` matches the order's.
- Everyone else, and orders without a PFI, get **404**, so other dealers can't tell whether an order exists.
- Response: `application/pdf`, `Content-Disposition: inline; filename="PFI-<number>.pdf"`, `Cache-Control: private, no-store`.

**Where the link appears:**
- **Dealer:** in the order page's documents list, the "Pro Forma Invoice (PFI)" row becomes a **View PFI** link (new tab) once the PFI exists.
- **Staff:** on the Orders page, the PFI number cell becomes a link.

## 6. Out of scope

- Odoo's own PDF, Odoo's `generateProForma` (left in the client, unused) and the messaging PFI-file route (unchanged).
- Terms and conditions text. Swift codes (blank on the template).
- Emailing the PFI, and a staff review step before the PFI.
- Changing VAT on the Odoo quotation itself.

## 7. Testing

- **Unit:** `pfiTotals` against the template's figures (above) and rounding in cents; the formatting helpers; the customer-ID fallback.
- **DB:**
  - submitting an order (mock Odoo) ends at **AWAITING_PAYMENT** with a PFI whose total is the subtotal + 8%, numbered with the SO number, carrying the signatory names, with amountDue = total;
  - `syncQuotation` stores `unitPriceExVat` and `quotedAt`;
  - legacy line prices are frozen;
  - an unknown station stays at QUOTATION_READY with the note, and staff Generate PFI can retry it;
  - the route rule allows the own dealer and Admin/SPE, and refuses another dealer, a Staff Member and a depot user.

  Existing tests that expect a new order to stop at QUOTATION_READY are updated to the new flow.
- **Visual:** render a generated PFI to PNG and compare it with the template.
- **Running app:** a dealer submits an order on a throwaway DB (test mode) and sees a VAT-inclusive amount due and a working View PFI; SPE opens the same PFI; another dealer gets a 404.
- **Full suite:** unit, DB, typecheck, lint, build.

## 8. Rollout

- **The migration is additive.** Apply it to staging, then production, with the guarded flow before deploying.
- **Production has no orders yet** (dealer ordering is off), so no backfill is needed.
- When ordering opens, dealers' amounts due include 8% VAT. Sales should be aware before go-live.
