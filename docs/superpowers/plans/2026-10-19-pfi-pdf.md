# Portal-generated PFI PDF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Right after an order's quotation is created, the portal issues a PFI (8% VAT on top, fixed signatories) and serves it as a PDF matching Trinity's Odoo template to the dealer and to Admin/SPE.

**Architecture:** Line prices and PFI totals are frozen in the database when the PFI is issued. A pure totals module does the maths in cents. A pdfkit renderer draws the PDF on each request from plain data. `GET /api/orders/[id]/pfi` serves it after a pure access check. `syncQuotation` calls `generatePfi` automatically, and the Odoo `generateProForma` call is dropped.

**Tech Stack:** Next.js 15 App Router, Prisma 6 / PostgreSQL, NextAuth v4, pdfkit 0.15.2 (new), node:test + tsx.

**Spec:** `docs/superpowers/specs/2026-10-19-pfi-pdf-design.md`

## Global Constraints

- VAT: **8% added on top** of the unit price before VAT. `vatRate` is stored as `"0.08"`.
- **Maths:**
  - line amount = round(litres × unitPriceExVat, 2);
  - subtotal = Σ line amounts;
  - vat = round(subtotal × 0.08, 2);
  - total = subtotal + vat;
  - all money is done in **integer cents**.
- Signatories: Prepared By and Approved By = `EVAN OTIATO`, both. Constants are copied onto each PFI when it's issued.
- **PFI number = `odooQuotationNumber`.** The PFI is issued automatically by `syncQuotation`. Staff "Generate PFI" remains as a retry.
- **No Odoo call when issuing a PFI.**
- Colours: primary `#3854a3`; footer gradient `#3854a3` → `#32c1d1`.
- **Formats:**
  - amounts: `1,110,777.78`;
  - volume: `6,000`;
  - unit price: 2 dp;
  - dates on the PDF: SO DATE `05 Oct 2026`, signature dates `05.10.2026`.
- PFI route: allowed for INTERNAL + `can(role,"retail.orders")`, or a DEALER of the same organisation. **Anything else → 404.**
  - Response headers: `Content-Type: application/pdf`, `Content-Disposition: inline; filename="PFI-<number>.pdf"`, `Cache-Control: private, no-store`.
- **Commits:**
  - no `Co-Authored-By` lines;
  - one branch, `feat/pfi-pdf` (already exists, with the spec).
- **Tests:**
  - new unit test files are added to `package.json` `"test"`;
  - new DB test files are added to `"test:db"`;
  - DB tests run against `tri_test` only.

## Review Focus

1. **Orders with non-fuel lines (LUBRICANTS/LPG)** must produce a PFI with **only the PMS and AGO lines**, the same lines the quotation sends. → Task 2 test.
2. **The automatic PFI and a staff "Generate PFI" retry arriving together** must leave exactly **one** PFI. → Task 2 test.
3. **A PFI issued before this change** (no frozen totals or line prices; exists on dev/staging) must still open, computed from the current price table, **without writing during the GET**. → Task 3 test.
4. **Another dealer, a Staff Member or a depot user** must get 404, not 403. → Task 4 test.
5. **A long dealer name or a long station name** must not push the PDF onto a second page or overlap the blocks. → Task 3 test (page count = 1).
